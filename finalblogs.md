## Dolat Capital

### Aakarshit Saxena

**Round 1: C++, OOPs and DSA. Write code on pen and paper for everything.**

It started with OOPs theory: what the six principles were, and explaining one principle in depth with an example. Then they moved directly to coding:

- Create a class and its object in C++.
- Create a child class and its object.
- Write constructors for both classes, create new objects, and explain the order/output of the constructors running.
- Show the different access modifiers in C++.

Thode bahut aur coding questions bhi the on OOPs.

Then came memory management, again with code on pen and paper:

- Loop through an array using a pointer.
- Implement a linked list using `struct`.
- Show pointers and references in code and explain the difference.
- Show how a dangling pointer is formed.
- Use `malloc`, `calloc` and `realloc`.

For DSA, I had to implement a stack using a linked list, solve another medium-level stack question, an array question combining two pointers and sliding window, a string-matching question, and a question on finding the intersection point of two linked lists.

They ask you to explain your code line by line, especially if it’s incorrect, and try to help you correct it. Toh keep answering and thinking aloud so they can understand your thinking and debugging skills.

**Round 2: Resume, DSA and CS core, without writing code on paper.**

They can pick up any word from your resume. Mere se LSTM ka architecture draw karne bola tha, R² ka formula pucha tha, and the transformer model explain karne bola tha. Be ready with both a 60–90 second explanation and a longer explanation of every project and experience on your resume.

In CS core, they asked how strings are stored in memory. In DSA, they asked about hashing, hash tables, hash maps, tree maps and red-black trees.

**Round 3 was HR.**

### Rounak Katiyar

The pen-and-paper test includes two questions. The first is a normal LeetCode medium-level DSA problem. The second is more important: an application-based problem using OOPs, where you design a data structure and some functions around it.

You need to write full, syntactically accurate code. A few mistakes are fine, and the work is judged by seniors.

After clearing the test, the interview is focused on C++ concepts, along with DSA and OOPs. C++ is the preferred language here, obviously.

## Wissen Technology

### Krish Tanna

The selection process started with an OA consisting of eight questions: two DSA questions, one SQL question, and five MCQs.

In my first technical interview, I was asked just two questions, one DSA and one SQL. The DSA question was between easy and medium level, mainly based on hashmaps. For SQL, they gave me a scenario and asked me to design an ER diagram and write a query based on it.

There was also a second technical interview, which I wasn’t selected for. From what I know, it involved system design and higher-level DSA questions.

For preparation, I’d recommend DSA topics like hashmaps, greedy, DP, and some trees and graphs. For SQL, be comfortable with joins and basic DBMS concepts. Going through basic system design would also help.

### Pratham Kitawat

**Online assessment**

The OA had six MCQs, two DSA questions, one on trees and one on arrays, and one SQL question. The tree question carried 50 marks, the array question 100, and SQL 25.

One coding problem was **Maximum Sensor Listening Score**. Given `T` time slots and `N` sensors, you could listen to at most `M` sensors in each slot. A sensor used at time `t` could only be used again at `t + D + 1` or later. You were given a `T × N` score matrix, with each sensor’s scores non-increasing over time, and had to maximize the total score. `T × N` could go up to `10^5`.

The SQL problem was **Course Completion Statistics**. There were `Employee`, `TrainingCourse` and `TrainingResult` tables. For each course, the report needed its ID, name, total employees who attempted it, and completion rate. Completion meant a score strictly greater than 50, and the percentage had to be rounded to two decimal places.

**Interview round 1**

1. **Email grouping:** Group email addresses by domain. For usernames longer than three characters, further classify them into lengths greater than five and lengths at most five. This was a coding problem, not SQL; Java or another preferred language could be used.
2. **First bad batch:** Find the first defective batch when all batches after it are also defective. The follow-up changed the sequence to good, then bad, then good again, and asked for the first good batch after the defective range.
3. **Database design and SQL:** Design a schema where authors can write multiple books, books can have multiple authors, and each edition has a unique ISBN. The follow-up asked for authors present in previous editions but not in later editions of a book.

**Interview round 2**

- A meeting-rooms problem asking for the minimum number of rooms required.
- A graph problem similar to LeetCode 210, Course Schedule II, involving dependency order/levels and cycle detection.
- One easy SQL question; I don’t remember the exact question.
- Design a printer-management system. Printers had IDs from 1–20, supported black-and-white or colour printing, and had pages-per-minute limits. Multiple users could submit requests, and the classes/interactions had to determine which printer was available. The focus was more on object-oriented design than implementation details or scheduling algorithms.

## Capgemini

### Yash Sodaye

The hiring process for my batch was:

1. Assessment test: technical aptitude, essay writing and a game-based test.
2. Coding round: optional, only for candidates scoring above the threshold.
3. SVAR Communication Test.
4. Technical + HR interview.

Focus on DBMS, OOPs and a little DSA. Prepare well for Round 1, since most candidates get eliminated there, and prepare from your resume too. There are plenty of online resources for the assessment.

Do check the latest hiring process. A friend had mentioned that there had been a few changes, so the process may differ from my batch’s.

### Riddhi Arya

They mostly asked questions based on my resume, at least in my case. Go through your resume properly and prepare for follow-up questions. Also revise the basics of the tech stack required for the job and learn a little about the company.

### Dishita Shah

Capgemini had three rounds of online tests. The first covered computer fundamentals like OS, CN, IS and pseudocode-type questions. The second had three medium-level coding questions. The third was cognitive.

## IKS Health

### Atul Pranay Chatti

A lot of the codebases being developed here are in Python, so they could ask fundamental questions on that, along with DSA.

My interview was much more resume-based: what I’d built during previous internships, my projects, and deep dives into those. They also asked me to explain concepts in a way a non-technical person could understand. For example, explaining Docker and containerisation to a layman.

Look at concepts from your own resume and practise explaining them simply. Mostly, prep your fundamentals, DSA and resume, like usual.
